# Customizer Panel: Blog (`phantom_blog`)

## Overview

The Blog panel controls the appearance and behavior of blog listing pages and single blog posts. It uses class-based layout toggling rather than CSS variables — the selected layout class (e.g., `blog-grid`, `blog-masonry`) is applied to the `.blog-posts` container, and CSS rules within the generated stylesheet respond to that class.

## Panel ID

`phantom_blog`

## Code Flow

### Layout Class Toggle (Live Preview)

```
User changes blog_layout in Customizer
  → save: phantom_blog_layout = "masonry"
  → customizer-preview.js postMessage handler
    → removes: blog-grid, blog-list, blog-masonry, blog-timeline from .blog-posts.classList
    → adds: blog-masonry to .blog-posts.classList
  → CSS rules in generated stylesheet apply:
      .blog-masonry { column-count: var(--blog-columns, 3); ... }
      .blog-grid { display: grid; grid-template-columns: repeat(var(--blog-columns, 3), 1fr); }
      .blog-list { display: flex; flex-direction: column; }
```

### Selective Refresh

The `blog_layout` and `blog_meta_layout` settings use `Selective Refresh` transport. When either changes:

1. Customizer sends partial refresh request for `phantom_render_blog_partial`
2. `partial-renderers.php` invokes `phantom_render_blog_partial()` which re-renders the blog grid HTML
3. The partial replaces the `.blog-posts` container DOM

### Settings → CSS Output

Blog settings do **not** generate CSS variables. Layout is handled entirely via:
- Class toggles on `.blog-posts` container
- Inline style attributes generated by `Blog_Card::render()` based on column/post settings
- The generated stylesheet contains responsive rules keyed to `.blog-grid`, `.blog-list`, `.blog-masonry`, `.blog-timeline`

### Frontend Templates

| Template | Usage |
|---|---|
| `frontend/html/blog.html` | Blog listing page — grid markup, pagination, sidebar |
| `frontend/html/single-blog.html` | Single blog post — content, meta, author box, related posts |
| `includes/renderer/class-blog-card.php` | `Blog_Card` renderer — outputs individual post card HTML |

### REST API Dependencies

Blog rendering uses data from:
- `GET /posts` — standard WP REST posts endpoint
- `GET /post/{id}` — single post data for detail view
- Post meta (categories, tags, author) included in REST response via `register_rest_field`

## Developer Notes

- **No CSS variables**: Unlike typography or color panels, blog layout is class-driven. The CSS modules (`includes/custom-css/blog.php`) generate rules for `.blog-grid`, `.blog-list`, `.blog-masonry`, `.blog-timeline` rather than CSS custom properties.
- **Column count**: `blog_columns` is stored as an integer but consumed as a CSS class modifier. `Blog_Card::render()` outputs `data-columns="{n}"` attribute; JS reads this and applies inline `--blog-columns` to the container.
- **Pagination**: `load_more` and `infinite_scroll` are JS-driven. The plugin loads `phantom-injector.js` which detects the pagination mode and attaches scroll/click handlers.
- **Selective refresh partial**: `phantom_render_blog_partial()` in `includes/partial-renderers.php` re-renders the entire blog grid HTML for live preview.
